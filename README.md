# Problem DSL – Exact Payment Problem

This folder contains the **Problem DSL**: a small domain metamodel, written with
[BESSER](https://github.com/BESSER-PEARL/BESSER) (B-UML), that describes the
*exact payment problem*. Given a wallet with a set of pieces (coins), a payment
asks to pay a target amount using some of those pieces.

The Problem DSL only describes **the problem**. It says nothing about how to
solve it. The solving part is handled by the Solution DSL (a linear integer
constraint model) and the model-to-model transformation in Part II.

## Files

| File | Description |
|------|-------------|
| `domain_model.py` | The metamodel (classes, associations, OCL constraints). |
| `complete_model.py` | The same metamodel plus the example object model (Ana's wallet). |
| `Class_Diagram.png` | Class diagram of the metamodel. |
| `Object_Diagram.png` | Object diagram of the example. |

## Metamodel

### Classes

| Class | Attribute | Type | Meaning |
|-------|-----------|------|---------|
| `Wallet` | `owner` | `str` | Name of the person who owns the wallet. |
| `Piece` | `label` | `str` | Name that identifies the piece (e.g. "2 euro cent coin"). |
| `Piece` | `value` | `int` | How much the piece is worth. |
| `Payment` | `amount` | `int` | Target amount to be paid. |
| `Payment` | `maxPieces` | `int` | Optional limit on how many pieces may be used. |

### Associations

| Association | Ends | Multiplicities |
|-------------|------|----------------|
| `wallet_pieces` | `wallet` (Wallet) – `pieces` (Piece) | a piece belongs to exactly one wallet (`1`); a wallet has any number of pieces (`0..*`) |
| `payment_wallet` | `paidFrom` (Wallet) – `payments` (Payment) | a payment is paid from exactly one wallet (`1`); a wallet can be used in many payments (`0..*`) |

Both are regular associations (not compositions). The payment points to the
wallet and not directly to the pieces, so the set of available pieces is
defined in one place and can be shared by several payments.

### OCL constraints

| Constraint | Context | Rule |
|------------|---------|------|
| `positiveValue` | `Piece` | A piece is worth more than 0. |
| `positiveAmount` | `Payment` | The amount to pay is greater than 0. |
| `amountReachable` | `Payment` | The amount cannot exceed the total value of the wallet. |
| `positiveMaxPieces` | `Payment` | If a limit is given, it is at least 1. |
| `uniqueLabels` | `Wallet` | Every piece in a wallet has a different label. |

## Example

The object model in `complete_model.py` represents this problem:

> Ana has a wallet with four coins: 2, 5, 10 and 20 euro cents. She wants to pay
> exactly 17 euro cents. Each coin can be used once and there is no limit on the
> number of coins.

| Object | Class | Attributes |
|--------|-------|------------|
| `ana_wallet` | `Wallet` | `owner = "Ana"` |
| `piece_1` … `piece_4` | `Piece` | values 2, 5, 10, 20, labels like `"2 euro cent coin"` |
| `payment` | `Payment` | `amount = 17`, `maxPieces` left empty |

All pieces are linked to `ana_wallet` through `wallet_pieces`, and `payment` is
linked to `ana_wallet` through `payment_wallet`.

## Usage

Install BESSER and import the models from Python:

```bash
pip install besser
```

```python
# Only the metamodel
from domain_model import domain_model

# Metamodel + example object model
from complete_model import domain_model, object_model

print([c.name for c in domain_model.types])
print([o.name for o in object_model.objects])
```

## Notes

- `maxPieces` is declared as a plain `int`, while `positiveMaxPieces` treats it as
  optional (`isEmpty()`). If your OCL tool complains about this, `oclIsUndefined()`
  is the usual alternative.
- Both Python files were generated by BESSER 8.1.0.
